# StockInfoDLSimple 整改发现

- 独立审查确认 `go_to_next_page` 将正常末页和 DOM 异常都返回 False。owner 的验证只见已保存文件，分页中断尚无键可追溯。
- 反向调用忽略最后一页跳转结果。配置上限路径在最后一个已计划页后仍点下一页。
- 既有原生 publisher 已管理 run/attempt、可重放收件包与普通启动回执，可复用其生命周期。
- 列表页与详情传输以前共用一个 browser page。详情 GET 后可能丢掉列表的位置与分页控件。现用同一浏览器上下文的独立详情页，并保留收到文件响应后的本地失败状态，已开始的同一传输没有第二次请求。
- 两种入口共用原运行账本。流水按业务步骤追加，标记、传输响应和业务终态分别由所属边界记录，诊断失败保持机器协议。合成例里的部分文件保留在原尝试的检查点，同一个下载任务因覆盖不完整非零。
