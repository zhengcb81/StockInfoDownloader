# TDD与完成标准

## TDD顺序

1. 为每项边界先写行为期待，注明现有合同与失败根因。RED必须来自真实越界/错误行为；缺依赖、沙箱权限、fixture拼错不计为产品RED。
2. 用最小公开替身或wire fixture体现边界：替身只有合同成员，访问其他属性直接报错；禁用邻仓imports/生产配置/网络后仍应成功。
3. 在owner内部改造配置注入、状态访问和适配；保留原有成功、错误、取消、partial、恢复语义。不能靠增加__all__、改成public名字、删断言或提高预算换绿。
4. 同一合同分别跑真实producer和consumer；覆盖两个可替换实现、无邻仓环境和实际交付包。仅在模块交付和最终组合做独立审查。
5. 每次改动跑相关集；已通过后不反复全量。最终模块候选跑其必要包级测试一次，组合阶段跑冻结矩阵一次；失败按所属owner修复后只复跑受影响部分。

## 分层测试

| 层 | 证明什么 | 实现方式 |
|---|---|---|
| U：纯域/策略 | 相同显式输入产生相同结果；配置/路径/时钟/网络不隐式介入 | 模块自身公开函数，真实正反样例；不patch邻模块私有helper |
| C：公开合同 | producer/consumer认识同一版本、成功/partial/错误/空值语义 | owner fixture +消费者decoder；可选新增字段可兼容，必需字段错误不冒成功 |
| I：模块隔离 | 纯reading不用解析SDK；consumer无法接触邻仓内部；只写自有状态 | 新进程、临时cwd、仅声明runtime可见、协议替身、失败注入与资源计数 |
| P：实际安装 | 当前产品wheel或skill runtime在无checkout布局时能启动/工作 | 按runtime_verification.md用正式构建/安装器；ET/SID无安装器时用明确runtime manifest复制。配置显式注入，重复安装幂等；不要部署全局副本 |
| E：组合 | 多个真实owner通过public transport工作，换物理路径也一致 | ROOT唯一组合suite；数据湖/输出/job都在隔离目录，用现行公开命令；真实本地样本只读 |

## ROOT一次组合的有限场景

| ID | 场景 | 关键断言 |
|---|---|---|
| E01 | CN/HK/US已有文档请求；含阿里及另一双上市发行人已有泛化夹具 | query复用不下载；issuer/挂牌市场与来源市场/期次字段正确，无公司分支 |
| E02 | 本地缺文档→SID或ET模拟供应端→CWP入库→再请求 | 第一次只采集一次，第二次零采集；原语言TXT可读；typed错误、限额/取消和staging清理正确 |
| E03 | 来源stream→两种parser替身/真实本地解析→reading | failed candidate不提交；只有公开protocol仍可使用同一OCR配置；单一预算不重复扣；locale/币种不在资料层猜改 |
| E04 | 真实本地三市场/多文种小样本 | 至少CN年/半年报PDF、HK业务说明PDF、US电话会TXT及一份DOCX IR；定位可回原文，换根目录不改变业务输入；资料召回原缺口单列父计划 |
| E05 | 同一摘要artifact的中断/同run/跨run恢复 | 本地可计数模型替身先证明不重复调用；坏可选日志不改成功，未知已付状态不盲目重发；真实收费恢复沿父计划后续验收 |
| E06 | CWP公开资料→RF/StockWiki→report catalog→Audit | 引用/版本/locator传递，研究状态只由研究owner写；不重跑已有有效预测；此项仅测接口贯通，不替代父计划买方质量/实际采用验收 |
| E07 | Sina已有小快照→FF statements→RF适配 | 三表合同、单位/来源/知识时点保留，第二次零HTTP；PDF parser不参与 |
| E08 | Dashboard配置的公开命令与版本组合 | code root/data root分离，既定必需能力真实成功；可选不支持能力有明确状态；不能用“unsupported”跳过必需场景 |
| E09 | 交付包入口清单与越界反控 | 当前默认工具不访问邻仓源码/SQL；退休工具不会被默认打包和自动调用；合法兼容单独测试，不扩大legacy豁免 |

ROOT在M2运行前选择实际已有样本source_id/version与locator并登记，不因结果换样本；这不阻碍五卡先用本仓fixtures开工。不扫描/复制全部公司资料。当前审查不声称已运行这些新场景。旧D4/D5/P3可复用为其中用例，但不能只把旧收据改日期。

## 环境和恢复

- 测试目录由各owner创建并拥有；初始清单为空时完整删除新增目录，非空时只删本次生成内容。原始文档只读；跨仓不写DB/config，费用账不回滚造假。
- Windows短临时根按实际路径能力选择；硬链接不可用时用可移植的复制/读取fixture，不改生产原子语义。测试输入与代码失败、工具环境失败分开。
- 付费/联网不属于本轮默认测试。真实网络能力确需验证时只跑相关一个入口、遵循现有配置和预算，不把外网临时失败当架构缺陷，也不能编成通过。
- 技术日志完整保存于本lane交接目录/临时结果，结束可压缩；不设置任意300KB/条数等输出许可。测试时限按现有配置与工作量，只对真实挂死做超时归因。

## 关闭判据（全部是工程结果，无人工许可）

1. 每个活动入口都有owner、公开接口及依赖规则；所有479个CWP源文件以及各repo交付入口均归类。没有未知入口靠共享目录豁免。
2. 已确认缺口CWP协议隐藏能力/默认配置/类型导入、RF旧工具/计算报告依赖/历史profile隔离、ET协议依赖、SID错误语义/metadata反向依赖均在对应版本有行为证明。静态风险（包括ET固定表示帽）先复现；FF若无缺陷以真实隔离契约通过交付，不强改。历史证据布局只要求兼容隔离，不要求重签或迁移所有旧执行包。
3. 每个模块仅依赖公开合同，内部模块可独立替换；其状态只能由owner持有/写入；负例能被测试/构建拦住。
4. 各repo的有效交付包在无邻仓源码的隔离环境通过；ROOT E01–E09按冻结适用范围完成，无必需场景skip。
5. 独立审查没有本范围阻断问题；候选与验收版本一致，合入正确主线并推送已有remote；无remote如实记录。仅docs更正不要求重跑业务。
6. 各lane工区可解释/清理，别人WIP保留，PWF统一CLOSED。立即回父计划R4/T4/摘要/恢复/RF循环；不再以其他业务改进延后这个架构阶段。

关闭代表当前声明产品边界已通过制度化验收，并非声称未来所有代码永无缺陷。未来越界在对应模块的同一测试机制中阻止，不重开全项目无边界整改。
